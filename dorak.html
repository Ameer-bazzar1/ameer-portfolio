The problem

Savings circles (jam‘iyya / dawrah) often run on WhatsApp, spreadsheets, and trust. Members miss payments, receipts get lost, and admins have no shared record of who paid and who is next to receive money. DORAK moves that process into an app: join a group, pay, review payments, move to the next round, and notify everyone — in Arabic and English.

What I built

Member app

Onboarding, login (email or phone), fingerprint/face unlock, home dashboard, browse groups, join requests, invitations and QR join, payment-photo upload, notifications, profile, and two-factor login.

Admin operations

Check ID documents, create and start groups, approve members, invite many people at once, review payments, set who gets paid and when, export group money reports as PDF.

Money layer

One money system for joining fees and monthly payments. The server sets the amount (the phone cannot send a fake number). Admins review payment photos. Every change is logged.

Reliability

Automatic payment reminders in the 7 days before a due date, phone push notifications, live updates, Redis cache, and cloud storage for receipts and ID photos.

Architecture

Client Flutter 3 · Firebase · secure storage · fingerprint/face unlock · Arabic layout (right to left)
API Django REST · PostgreSQL · Redis · Celery + Beat · Django Channels
Cloud Railway / Render · Docker · Firebase · Cloudinary · HTTPS

Security I owned in the product

  • Two-factor login (email/SMS). One-time codes are stored hashed. Extra checks before changing email, phone, or password.
  • Login sessions expire after 30 days. Logout and password change sign you out everywhere.
  • Limits on how often someone can try to log in or register from the same IP.
  • Money rules on the server: a user cannot approve their own payment or create a payout.
  • Database row-level security on payments, notifications, ID checks, and group membership.
  • On the phone: block screenshots on code/password screens; extra checks if the device is rooted or jailbroken.
